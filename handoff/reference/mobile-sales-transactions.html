Proposal
Mobile web view — Sales transactions
Responsive web layout for ≤768px, same components and styling as desktop. Fixes the three issues: oversized top bar, horizontal table scrolling, and the disappearing-bar gap.
1 · Compact sticky bar (never vanishes). The page bar is sticky and collapses on scroll-down to a single 34px summary strip — count, active range, filter count, and a "Search & filters" pill to reopen it. No empty gap, controls always one tap away. The global module-search bar scrolls away normally.
2 · One-row toolbar + chips. The five stacked selects (All time, Custom range, No grouping, EUR, Columns) become one search field + a Filters button opening a bottom sheet. Active filters show as removable chips in a horizontally scrollable row.
3 · Cards instead of table rows. Each transaction is a 3-line card: ID + status + date / channel + fulfilment + SKU / money line (net, fee, profit € and %). No horizontal scrolling; tap a card for full detail. Bulk-select via long-press or an Edit mode in ⋯.
4 · Bottom sheet for filters. All data controls in one thumb-reachable sheet with 40px rows; Columns becomes "Visible fields" controlling which card fields render.
5 · Header actions stay compact. Alerts becomes an icon with a status dot, secondary actions stay in ⋯, primary shortens to "+ Register" and never wraps.
Breakpoints
≥1024px — desktop two-row bar (approved design)
768–1023px — desktop bar, toolbar wraps to two rows
≤767px — this layout: card list, chips, bottom sheet, collapsing summary strip
